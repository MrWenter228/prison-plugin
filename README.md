# Prison

Самописний Minecraft Prison-плагін (Spigot/Paper, Java 17) у стилі VimeWorld:
шахти з автовідновленням, система рівнів 1-40, тірова прокачка спорядження,
аукціон гравців, дві валюти, локалізація з градієнтами.

## 🚀 Найпростіший спосіб отримати jar: GitHub Actions

У репозиторії лежить `.github/workflows/build.yml`. Достатньо залити код на
GitHub (через веб-інтерфейс, GitHub Desktop або `git push`) — вкладка
**Actions** сама збере `Prison.jar` і покладе його в **Artifacts** цього
запуску. Якщо запушите тег (`git tag v1.0.0 && git push origin v1.0.0`),
workflow додатково створить офіційний **Release** із прикріпленим jar-ом.

## Локальна збірка

```bash
mvn clean package
```

Готовий `Prison.jar` з'явиться в `target/`. Компілюється проти Paper API
1.20.4-R0.1-SNAPSHOT, а в `plugin.yml` заявлено `api-version: '1.16'` для
максимально широкої сумісності (від 1.16.5 і вище). Чесне застереження: код
навмисно тримається лише стабільного legacy Bukkit API (без Adventure
Components, без API новіших за ~1.20), тож теоретично працює й на значно
новіших версіях, але я фізично не можу протестувати це на версіях, яких не
існувало на момент написання коду.

## Встановлення

1. Покладіть `Prison.jar` у папку `plugins/` вашого сервера.
2. Перезапустіть сервер — згенеруються `config.yml`, `mines.yml`, `prices.yml`, `lang/*.yml`.
3. Виконайте `/minewand` (потрібен `prison.admin`, за замовчуванням OP), виділіть
   регіон майбутньої шахти (ЛКМ = поз.1, ПКМ = поз.2).
4. `/mineset create mine_a` — створить шахту (доступну одразу всім гравцям, без будь-якого рангового замка).
5. `/mineset setblock mine_a STONE 70` та `/mineset setblock mine_a COAL_ORE 30`
   (сума відсотків складу має дорівнювати 100).
6. `/mineset settp mine_a` — стоячи в потрібному місці, встановіть точку спавну шахти.
7. Готово — гравці можуть `/mines mine_a`, `/lvl`, `/upgrade`, `/autosell on`.

## Основні команди

| Команда | Опис |
|---|---|
| `/lvl` (аліаси `/level`, `/levels`) | Компактне меню рівня - одна пляшка досвіду, клік підвищує рівень |
| `/mines [назва]` / `/minesgui` | Список шахт (текстом / GUI) - усі шахти відкриті всім гравцям |
| `/upgrade` (аліаси `/up`, `/gear`, `/prokachka`) | Тірова прокачка предмета в руці (як на VimeWorld) |
| `/pay <гравець> <сума>` | Переказ **лише монет** (рублі - донат-валюта, між гравцями напряму не передаються) |
| `/autosell <on\|off\|all>` | `on/off` - автопродаж при копанні; `all` - миттєво продати весь інвентар |
| `/auc` \| `/rauc` (кожна з `sell <ціна> [гравець]`) | Два окремих аукціони - за монети та за рублі, повнофункціональне GUI |
| `/lvl set <гравець> <рівень>` (адмін) | Примусово встановити рівень будь-якого гравця (1-40) |
| `/booster` \| `/booster give <гравець> <coins\|blocks> <2\|3\|5> <day\|week\|month>` (адмін) | Магазин бустерів x2/x3/x5 за рублі / безкоштовна адмінська видача |
| `/money give <гравець> <сума>`, `/rubles give <гравець> <сума>` (адмін) | Видача монет / рублів (донат-валюта) гравцю |
| `/minewand`, `/mineset ...` | Адмін-інструменти створення шахт |

> `/balance`, `/bal`, `/baltop` та `/prisoninfo` видалені - баланс і прогрес видно через `%prison_balance%`/`%prison_level%` (PlaceholderAPI, скорборд/tab) або лор у меню `/lvl` та `/booster`.

## Система рівнів 1-40 (як на VimeWorld)

`/lvl` відкриває найпростіше можливе меню - один рядок з 9 слотів (Minecraft
не дозволяє менші chest-інвентарі, 7 слотів фізично неможливі), з єдиним
активним предметом по центру - **пляшкою досвіду**. Її лор завжди показує:
поточний рівень, скільки блоків видобуто/потрібно, вартість переходу.

Щоб піднятись на наступний рівень, потрібно ОДНОЧАСНО:
1. видобути в шахті певну кількість блоків з моменту останнього рівня;
2. заплатити монети.

**Вимоги для кожного рівня - НЕ формула, а готова таблиця** (`config.yml` →
`levels.requirements`), один рядок на кожен цільовий рівень 2-40, скопійована
з реальних чисел VimeWorld - тому прогресія нерівномірна (наприклад рівень 7
взагалі не вимагає блоків, лише монети). Кожен рівень дає постійний % бонус
до автопродажу (`levels.reward-multiplier-per-level`).

**Рівень постійно показується на ванільній XP-панелі гравця** (число над
смужкою досвіду = ігровий рівень плагіна, заповнення смужки = прогрес блоків
до наступного рівня) - оновлюється при вході, після кожного видобутого блоку
й одразу після підвищення рівня (`LevelManager#updateXpBar()`).

Адміни можуть встановити рівень будь-якого гравця напряму, в обхід вимог:
`/lvl set <гравець> <рівень>` (скидає прогрес блоків до 0, потрібен `prison.admin`).

## Тірова прокачка спорядження (`/upgrade`, як на VimeWorld)

На відміну від абстрактних рівнів зачарування, тут **сам предмет фізично
змінює матеріал** - точнісінько як апгрейд кирки на VimeWorld:

```
Дерево (Eff 0) -> Дерево Eff I (монети) -> Камінь Eff I (+ камінь) ->
Залізо Eff II (+ залізо) -> Алмаз Eff III (+ алмази)
```

Той самий принцип застосовано до **мечів** (Гострота замість Ефективності) і
**броні** (Захист замість Ефективності, ланцюжок Шкіра -> Залізо -> Алмаз).

**Лопати - окрема категорія від кирки/сокири**, з власною 12-тірною
драбиною і своєю сировиною (**земля, пісок і гравій** замість руди - тема
"копання"):
```
Дерево -> Дер. Eff I -> Дер. Eff II -> Дер. Eff III ->
Камінь Eff I -> ... -> Камінь Eff IV ->
Залізо Eff I -> Залізо Eff II -> Залізо Eff III ->
Залізо Eff III + Удача I (фінальний тір, два зачарування одразу)
```

Кожен перехід коштує монети **і** конкретну сировину (config:
`upgrades.<tool|shovel|sword|armor>.tiers`) - кількість налаштовується
окремо для кожного кроку. Тір може нести **більше одного зачарування
одночасно** (як фінальний тір лопати - Ефективність III + Удача I) - формат
`enchants: [{enchant: ..., level: ...}, ...]` у конфізі.

**Головна вимога виконана буквально**: кожен апгрейднутий предмет одразу
отримує `ItemMeta#setUnbreakable(true)` - кирка, сокира, лопата, меч чи
броня після проходження хоча б одного кроку прокачки більше ніколи не
ламається, незалежно від матеріалу.

Поточний тір предмета НЕ зберігається окремо (жодних PDC-тегів) - він
визначається напряму з фізичних властивостей предмета (матеріал + повний
набір зачарувань), що завжди однозначно відповідає одному з рядків `tiers`
у конфізі.

`/upgrade` малює драбину тірів зліва направо однією іконкою на слот:
пройдені тіри позначені зеленим, поточний світиться, наступний - клікабельний
з ціною, решта показані бар'єром з підказкою "спочатку прокачайте попередній".

## Захист спорядження при смерті

При смерті гравця **кирка, сокира, лопата, меч, вся броня, ножиці та вудка НЕ
випадають** на землю - вони знімаються зі списку дропу в момент смерті й
автоматично повертаються гравцю (броня одразу одягається назад у слоти, якщо
ті вільні) одразу після респавну. Все інше (блоки, їжа, звичайні предмети)
випадає як завжди у ванільному Minecraft. Реалізовано в `DeathProtectionListener`.

## Дві валюти

- **Монети** (`balance`) - основна валюта, поповнюється видобутком/автопродажем блоків у шахтах, витрачається на рівні й прокачку спорядження. Переказ між гравцями - `/pay <гравець> <сума>`.
- **Рублі** (`rubles`) - друга валюта (донат). Гравцям НЕ передається напряму (`/pay` працює лише з монетами) - рублі отримують через аукціон (`/rauc`) або адмінську видачу `/rubles give <гравець> <сума>`.

Баланс не має окремої команди перегляду - видно через `%prison_balance%` / `%prison_rubles%` (PlaceholderAPI) або лор у GUI `/booster`.

Адмінська видача валюти (потрібен `prison.admin`):
- `/money give <гравець> <сума>` - видати монети
- `/rubles give <гравець> <сума>` - видати рублі

## Аукціон (`/auc` за монети, `/rauc` за рублі)

Два повністю окремих ринки з однаковим функціоналом - `/auc` торгує лише за
монети, `/rauc` - лише за рублі (одна і та ж команда `AuctionCommand`
всередині, валюта фіксується при реєстрації).

**Виставлення лота:**
- `/auc sell <ціна>` - публічний лот, бачать усі
- `/auc sell <ціна> <гравець>` - **персональна пропозиція** конкретному гравцю (більше ніхто її не бачить і не може купити)

**GUI (54 слоти):** верхні 45 - самі лоти, нижній ряд - панель навігації:

| Слот | Кнопка | Дія |
|---|---|---|
| 45 | Назад | Скидає фільтри - вкладка "Усі", сортування за замовчуванням, 1 сторінка |
| 46 | Усі предмети | Публічні лоти цієї валюти |
| 47 | Персональні пропозиції | Лоти, виставлені персонально для вас |
| 48 | Мої лоти | Все, що виставили ви (публічне + персональне) |
| 49 | Сортування | Клік циклічно перемикає: нові → старі → ціна зростає → ціна спадає |
| 50 | Статистика | Клік надсилає в чат: скільки активних лотів, скільки ваших і на яку суму, скільки персональних пропозицій чекає на вас |
| 51 | Оновити | Перемальовує поточний вигляд (корисно після того, як хтось купив/продав) |
| 52/53 | ◀ / ▶ | Попередня / наступна сторінка |

Кожен лот у лорі показує продавця, ціну+валюту, і **скільки часу лот ще
буде висіти на аукціоні** (`config.yml` → `auction.listing-duration-hours`,
за замовчуванням 72 год). Клік по чужому лоту - купівля, по своєму - зняти
з продажу (предмет повертається в інвентар).

**Протухлі лоти:** фонова задача (`auction.expiry-check-interval-seconds`)
знімає лоти, термін яких вийшов. Якщо продавець зараз онлайн - предмет
одразу повертається в інвентар; якщо офлайн - лягає в персональну "пошту"
(`MailboxManager`, `mailbox.yml`) і видається автоматично, щойно гравець
зайде на сервер (з попередженням у чат).

Лоти зберігаються в `auctions.yml`, переживають рестарт сервера. Ліміт
одночасних лотів на гравця та максимальна ціна - `config.yml` → `auction.*`.

## Бустери монет і блоків (`/booster`)

Магазин тимчасових множників за рублі, кожен доступний одразу на **трьох
рівнях сили** - x2, x3, x5:

- **Бустер монет** - на час дії множить виторг з кожного проданого блоку
- **Бустер блоків** - на час дії множить прогрес до наступного рівня за кожен видобутий блок

Кожна сила купується окремо на **день / тиждень / місяць** (`config.yml` →
`boosters.coins.tiers.<2|3|5>.price-*` та аналогічно для `blocks`, у рублях,
18 комбінацій разом). Повторна покупка **додає** термін до вже активного
бустера, а сила одразу перемикається на щойно куплену.

`/booster` відкриває магазин (статус активності + сітка кнопок для обох
типів). Адміни можуть видати бустер безкоштовно:
```
/booster give <гравець> <coins|blocks> <2|3|5> <day|week|month>
```

## Пасивні бонуси за рівень (серця та урон)

Реальні Bukkit `AttributeModifier` (не косметика - справді впливають на
геймплей), перераховуються при вході та після кожного підвищення рівня:

- **Додаткові серця здоров'я** - `perks.hearts.levels` (список рівнів, кожен
  дає +1 серце), обмежено `perks.hearts.max-bars` (за замовчуванням 4
  полоски = 80 HP разом із базовою).
- **Додатковий урон** - `perks.damage.levels` (за замовчуванням починається
  з рівня 12), обмежено `perks.damage.max-bonus` (за замовчуванням +6).

## Обмеження ігрового світу

Щоб не заважати кастомній системі рівнів і власній економіці:
- **Крафт повністю вимкнено** (будь-який рецепт через верстак чи власний інвентар).
- **Досвід за вбивство мобів не нараховується** - ванільна XP-панель повністю
  контролюється `LevelManager` і показує ігровий рівень плагіна, а не
  справжній досвід.

Реалізовано в `RestrictionListener` (скасовує `CraftItemEvent` та обнуляє `EntityExpEvent`).

## Локалізація та градієнти

Мова інтерфейсу (`ru`/`en`) задається через `config.yml` → `language.default`
(командного перемикача немає, але самі файли перекладу повністю робочі й
легко редагуються). У будь-якому рядку `lang/*.yml` можна використовувати:

```yaml
level-up-success: "&#FF00FF&#00FFFFВи досягли рівня {level}!"
some-message: "&#FF00AAСуцільний hex-колір без градієнта"
```

`&#HEX1&#HEX2текст` - два hex-коди підряд запускають плавний перехід кольору
по символах до наступного `&`-коду чи кінця рядка. Обробку виконує
`GradientUtil` через `net.md_5.bungee.api.ChatColor.of(Color)`.

**Персоналізація часу**: скорочення одиниць часу (дні/години/хвилини), що
показуються в лорі лотів аукціону та бустерів ("2д 5г", "3г 12м"), НЕ
захардкоджені в коді - беруться з `lang/*.yml` → `time-days` / `time-hours` /
`time-minutes`. Хочете "2дн 5ч" замість "2д 5г" - просто відредагуйте ці три
рядки у своєму мовному файлі, код чіпати не треба (`util/TimeFormatter`).

## Архітектура

```
com.prison.core
 ├─ PrisonPlugin          — точка входу, DI менеджерів, таски
 ├─ managers/
 │   ├─ MineManager         — mines.yml, регіони, async-батчований реген
 │   ├─ EconomyManager      — prices.yml, продаж, level-множник
 │   ├─ PlayerDataManager   — playerdata/<uuid>.yml, кеш (+ locale гравця)
 │   ├─ LanguageManager     — lang/*.yml, градієнти/hex, per-player локаль
 │   ├─ LevelManager        — система рівнів 1-40 (блоки+монети), XP-панель
 │   ├─ UpgradeManager      — тірова прокачка (матеріал+зачарування, VimeWorld-стиль)
 │   ├─ AuctionManager      — аукціон гравців (auctions.yml, list/buy/cancel, персональні пропозиції, термін дії)
 │   ├─ MailboxManager      — "пошта" для предметів з протухлих лотів офлайн-гравців
 │   ├─ BoosterManager      — множники монет/блоків x2/x3/x5, куплені за рублі
 │   ├─ PerksManager        — пасивні бонуси за рівень (серця, урон - AttributeModifier)
 │   └─ SelectionManager    — тимчасовий pos1/pos2 для wand-а
 ├─ model/                 — Mine, PlayerData, Currency, AuctionListing (POJO)
 ├─ commands/               — по одному класу на команду
 ├─ gui/                    — LevelGUI, MinesGUI, UpgradeGUI, AuctionGUI, BoosterGUI + holders + GUIListener
 ├─ listeners/              — BlockBreak (autosell+прогрес рівня), Join/Quit,
 │                            wand-клік, DeathProtectionListener, RestrictionListener (крафт/mob-XP)
 └─ util/                   — ItemBuilder, GradientUtil (hex/градієнт парсер), TimeFormatter (персоналізовані одиниці часу)
```

### Ключові механіки

- **Шахти відкриті всім**: система рангів видалена - будь-яка створена
  адміном шахта одразу доступна кожному гравцю через `/mines` чи `/minesgui`.
- **Async-батчований реген шахт**: фонова задача (`mines.check-interval-seconds`)
  робить вибіркову перевірку заповненості; при падінні нижче
  `mines.auto-reset-threshold` `MineManager` запускає `BukkitRunnable`, який
  ставить лише `mines.regen-blocks-per-tick` блоків за тік - без lag-spike
  навіть на дуже великих шахтах.
- **Автопродаж + прогрес рівня**: при видобутку блоку сума одразу
  конвертується в гроші (з урахуванням `levels.reward-multiplier-per-level`
  та активного бустера монет), і водночас блок (з урахуванням бустера блоків)
  зараховується в лічильник прогресу до наступного рівня.
- **Пасивні бонуси синхронізуються з рівнем**: `PerksManager` перераховує
  AttributeModifier здоров'я/урону при вході та після кожного підвищення рівня.
- **Персистентність**: власне YAML-сховище на гравця замість Vault/SQL.

## PlaceholderAPI

Якщо на сервері встановлено й увімкнено PlaceholderAPI, плагін автоматично
реєструє плейсхолдери:

| Плейсхолдер | Опис |
|---|---|
| `%prison_balance%` | Баланс монет, відформатований |
| `%prison_rubles%` | Баланс рублів, відформатований |
| `%prison_level%` | Поточний рівень гравця (1-40) |
| `%prison_level_max%` | Максимальний рівень (40) |
| `%prison_level_progress%` | Блоків видобуто/потрібно до наступного рівня |

Реалізовано в `com.prison.core.placeholder.PrisonPlaceholders`. Клас
завантажується лише якщо `PluginManager#getPlugin("PlaceholderAPI") != null` -
без встановленого PlaceholderAPI плагін просто пропускає цей крок.

## Можливі наступні кроки (не реалізовано)

- Частинки/звук при підвищенні рівня чи тіра прокачки.
- MySQL-бекенд для playerdata замість YAML (для мереж із кількома серверами).
- Гейтинг доступу до шахт за рівнем гравця (зараз усі шахти відкриті всім).
